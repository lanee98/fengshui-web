# 表达层规范（L3）

`scripts/check.py` 输出的 JSON 已经完成了**对象名映射、方位名计算、占位符替换**，
所以表达层只剩三件事：**排语气、控结构、守红线**。

不要把这里当成"润色"环节。规则已经判完了，表达层改的是**说法**，不是结论。

---

## 输入

`check.py` 的输出 JSON。关键字段：

```json
{
  "summary": { "violations": 9, "by_severity": {"high": 5, "medium": 3, "low": 1}, "passed": 9, "skipped": 0 },
  "violations": [
    {
      "rule_id": "FS-BED-001",
      "name": "床头靠实墙",
      "severity": "high",
      "objects": ["BED-S", "W-N"],
      "object_labels": ["次卧床", "北墙"],
      "violation_text": "床头悬空或靠窗。传统居住观念认为……",
      "suggestion": "将 次卧床 床头旋转至紧邻实墙，贴合 0.05 m 以内。",
      "detail": "床头边距最近实墙 0.85 m，超过贴墙阈值 0.05 m"
    }
  ],
  "passed_rules": [ ... ],
  "skipped": [ ... ]
}
```

`suggestion` 里的 `{object_id}` 已经换成「次卧床」，**直接用，不要再替换**。

---

## 输出结构

### 汇总段

- 有违规：先说总数与优先级——「本次方案共 9 处提示，其中 5 项建议优先处理。」
- 零违规：给正面反馈——「当前布局通过了全部 18 项空间检查，包括风水文化参考项。可以进入下一步。」
  不要写成"风水很好"，那是在承诺功效。
- 有 `skipped`：必须单独说——「另有 1 项因缺少梁数据未能检查。」
  **不能让用户以为跳过 = 通过**，这是最容易出问题的地方。

### 单个违规卡片

严重度决定语气，这是唯一的语气开关：

| severity | 语气 | 开头 |
|---|---|---|
| `high` | 明确建议修改 | 「强烈建议调整：」 |
| `medium` | 温和建议 | 「建议考虑：」 |
| `low` | 可选提示 | 「可以考虑：」（并注明可在设置中关闭） |

卡片内容用四段：**标题（规则名）→ 现状（用 `detail`）→ 解释（用 `violation_text`，不改写）→ 建议（用 `suggestion`）**。

`violation_text` 已经是「传统观念认为……；从 X 角度看……」的双解释结构，**照抄，不要重写**。
改写会把红线重新引进来。

### 两档长度

- **短版**：AR 悬浮标签用，每张 ≤ 40 字，只保留"对象 + 问题 + 一步动作"。
  例：`次卧床：床头未靠实墙。建议旋转至北墙。`
- **长版**：详情面板/导出报告用，完整四段。

两档内容必须一致，短版是长版的压缩，不是另一个结论。

### 文化参考段（仅当 `culture_reference.enabled` 为真）

命卦模块的结果单独成段，规则和违规卡片**完全不同**：

- **位置永远在最后**，前面加分隔线和一句「以下为文化参考，与上方空间判定无关」。
- **不计入统计。** 开头那句「共 N 处提示」只统计 `violations`，命卦结论绝不并进去。
- **语气是陈述流派约定**，不是对业主下判断。写「按八宅派约定，二者不同组」，不写「这套房子不适合你」。
- **`limits` 必须一起给出**，不能等被问才说。它是 `culture_reference.limits` 数组，直接列。
- **`matched: false` 时不许顺势给改动建议。** 不能说「建议把床头转向X方以合命卦」——那是把文化解释伪装成设计结论，整条论证链会被这一点击穿。
- `available: false` 时如实说缺什么（缺生辰 / 缺入户门），不要说成"通过"。

---

## 语言红线

这几条是产品能否被接受的底线，比"说得好听"重要得多。

1. **不做吉凶断言。** 不说「大凶」「破财」「会生病」「影响运势」「不吉利」。
   说「传统居住观念认为……」「从环境心理角度看……」。
2. **不承诺功效。** 不说「调整后家人更健康」「这样摆能聚财」。
   风水在这里是**文化参考 + 空间约束**，不是功能承诺。
3. **不加强原文语气。** `violation_text` 已经是克制写法，不要为了"有说服力"加码。
4. **不给绝对化结论。** 用「建议」「可以考虑」，不用「必须」「一定」。
5. **跳过要说跳过。** `skipped` 的规则不能默认成"通过"。
6. **文化参考不得越界。** 命卦结论不能写进 `violations`、不能进入统计、不能生成改动建议、不能省略 `limits`。
   它是解释，不是判定——两者混一起，前面 18 条的国标论证会被一起拖下水。

---

## 出处怎么用

出处信息**不在** JSON 里，在 `references/evidence.md`。规则：

- **短版一律不带出处**，AR 标签放不下，也没人看。
- **长版默认不带**，用户主动问"凭什么"或进入"依据"折叠区时才给。
- **给的时候看核对状态**：
  - ✅ 可以报页码：「《图解阳宅十书》p.458」
  - ⚠️ 只说书名，**不报页码**：「《阳宅十书》有相关记载」
  - 🔶 必须说明是转引：「据通行引用归于《阳宅三要》」
- **国标优先**：能用 GB 55038-2025 解释的，先给国标，再补文化维度。
  这是回应"风水是不是迷信"最有效的一句话。

## 完整示例

输入（节选）：

```json
{
  "summary": {"violations": 2, "by_severity": {"high": 1, "medium": 1}, "passed": 16, "skipped": 0},
  "violations": [
    {"rule_id": "FS-BED-001", "name": "床头靠实墙", "severity": "high",
     "object_labels": ["次卧床", "北墙"],
     "violation_text": "床头悬空或靠窗。传统居住观念认为床头缺乏实墙依靠则缺乏安全感；环境心理角度，贴实墙入睡的确定感更高。",
     "detail": "床头边距最近实墙 0.85 m，超过贴墙阈值 0.05 m",
     "suggestion": "将 次卧床 床头旋转至紧邻实墙，贴合 0.05 m 以内。"},
    {"rule_id": "FS-KIT-001", "name": "灶台-水槽间距过近（「水火不相冲」几何转译）", "severity": "medium",
     "object_labels": ["灶台", "水槽"],
     "violation_text": "灶台与水槽间距过近。传统有「水火不相冲」之说；操作安全上，油溅遇水、动线交叉也确实不利。",
     "detail": "灶台与水槽最小间距 0.15 m，低于 0.60 m",
     "suggestion": "拉开灶台与水槽间距至 ≥ 0.60 m，或中间插入操作台。"}
  ]
}
```

短版：

```
次卧床：床头距墙 0.85 m，未靠实墙。建议旋转至北墙。
灶台：与水槽仅隔 0.15 m。建议拉开至 0.6 m 以上。
```

长版：

```
本次方案共 2 处提示，其中 1 项建议优先处理。

【床头靠实墙】建议优先处理
现状：次卧床床头边距最近实墙 0.85 m，超过 0.05 m 的贴墙阈值。
说明：传统居住观念认为床头缺乏实墙依靠则缺乏安全感；环境心理角度，贴实墙入睡的确定感更高。
建议：将次卧床床头旋转至紧邻实墙，贴合 0.05 m 以内。可在 AR 中一键应用。

【水火不相冲】建议考虑
现状：灶台与水槽最小间距 0.15 m，低于 0.60 m。
说明：传统有「水火不相冲」之说；操作安全上，油溅遇水、动线交叉也确实不利。
建议：拉开至 0.60 m 以上，或中间插入操作台。
```

## 闭环（演示重点）

`check.py` 每条违规都带 `objects`（机器可读 ID）。如果 `fix` 类型是引擎能执行的
（`rotate_translate` / `translate` / `rotate` / `add_partition`），在建议后加一句
「可在 AR 中一键应用」。

调整后重跑 `check.py`，对比 `rule_ids` 变化——**「提示 → 一键调整 → 复检通过」**
这个闭环是整个产品最有说服力的部分，汇报时一定要演。
