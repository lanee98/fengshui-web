# 场景数据格式

`scripts/check.py` 的输入。一个 JSON 文件，描述一套户型的俯视平面。

## 坐标约定

- 单位：**米**。仅支持俯视 2D（x, y），高度只用于「高家具遮光」判定。
- 原点任意，推荐取**西南角**为 (0,0)。
- x 向右为东，y 向上为北。
- 角度用**度**，`0°` 指向 +x（东），逆时针为正。`heading` 表示家具**主朝向**。

`heading` 的语义按家具类型各有约定，判定依赖它们，别搞反：

| 类型 | heading 指向 | 判定含义 |
|---|---|---|
| `bed` | 脚的方向 | `heading` 的**反方向**那条边是**床头边**（靠墙判定用） |
| `sofa` | 坐的人面朝方向 | 反方向那条边是**沙发背**（靠山判定用） |
| `stove` / `sink` | 操作面朝向 | 仅用于视线锥判定 |
| `mirror` | **镜面法线**（镜子照向的方向） | 用来判断"镜子是否照到床/大门" |

## 顶层结构

```json
{
  "meta":      { "name": "户型名", "unit": "m", "origin": "southwest" },
  "walls":     [ ... ],
  "doors":     [ ... ],
  "beams":     [ ... ],
  "furniture": [ ... ],
  "rooms":     [ ... ]
}
```

`walls` / `doors` / `furniture` 是**必需**的，缺了会让相关规则记入 `skipped` 而不是静默通过。
`beams` 缺省时「横梁压床」跳过（这是设计允许的降级：v1 拿不到梁数据时如实告知用户）。
`rooms` 缺省只影响 `room_of()` 的房间归属，不影响判定。

### meta.owner（可选，仅文化参考模块用）

```json
"meta": {
  "name": "示例户型",
  "owner": { "birth_year": 1998, "birth_md": "06-15", "gender": "female" }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `birth_year` | 是 | 公历出生年，四位 |
| `gender` | 是 | `"male"` / `"female"`，命卦男女算法不同 |
| `birth_md` | 否 | `"MM-DD"`，给了才做立春校正（1/1–2/3 出生归上一年） |

**这个字段和 18 条判定完全无关**，只在加 `--culture` 时被读取。不填则文化参考段显示"未提供居住者信息"，
其余检查照常。算法与局限见 `minggua.md`。

### walls

```json
{ "id": "W-N", "a": [0.0, 9.6], "b": [8.4, 9.6], "is_window": false }
```

- `is_window: true` 的墙段视为**窗墙**：不遮挡视线、不能作为床头/沙发的"实墙靠山"、可作为「穿堂煞」与「窗前遮光」的对象。
- 同一面墙可以拆成多段（例如北墙上开一段窗，就要把实墙段和窗段分成两个 wall）。
- 门**不要**从墙里挖洞——门单独放在 `doors`，墙保持连续即可。

### doors

```json
{
  "id": "D-entry", "name": "入户门",
  "center": [4.2, 0.0], "normal": [0.0, 1.0],
  "width": 0.9, "is_entry": true
}
```

- `normal` 必须**指向室内**（人进门后走的方向），它决定所有"视线锥"判定朝哪开。
- `is_entry: true` 的那扇才算入户门；没标则退化为 `doors[0]`。
- `name` 会出现在给用户的文案里，请写人话（"卫生间门"而不是"门2"）。规则里靠 `name` 含"卫"/"厨"或 `id` 含 `bath`/`toilet`/`kit` 来识别房间类型，命名时留意。

### beams

```json
{ "id": "BM-1", "name": "次卧横梁", "a": [5.2, 7.2], "b": [8.4, 7.2], "width": 0.3 }
```

梁按"线段 + 宽度"表达，判定时展开成俯视投影带。

### furniture

```json
{
  "id": "BED-M", "name": "主卧床", "type": "bed",
  "rect": { "cx": 1.8, "cy": 8.58, "len": 2.0, "wid": 1.8, "heading": 270 },
  "height": 0.5
}
```

- `rect` 是**旋转矩形**：中心 `(cx, cy)`、长 `len`（沿 heading 方向）、宽 `wid`（垂直 heading）、朝向 `heading`。
- ⚠️ **`len` 和 `wid` 填哪个方向，取决于家具怎么摆，不要照抄"长"和"宽"**：

  | 类型 | `len`（沿 heading） | `wid`（垂直 heading） |
  |---|---|---|
  | `bed` | 床长 2.0 | 床宽 1.8 |
  | `sofa` | **进深 0.9** | **长度 2.2** |
  | `stove` / `sink` | 台面宽 | 进深 |

  沙发最容易填错：人坐着朝 heading 看，进深方向沿 heading，座位长度是垂直方向。
  填反了不会报错，但家具形状就横过来了，判定结果全歪。
- `type` 取值：`bed` `sofa` `stove` `sink` `mirror` `wardrobe` `table` `tv` `toilet` `other`。
  未知值一律按 `other` 处理，不会报错，但也不会被任何规则命中。
- `height` 只影响「窗前遮光」（阈值 1.2 m）和「沙发人造靠山」（≥ 1.2 m 的高柜算靠山）。
- `name` 出现在文案里，写人话。

### rooms

```json
{ "id": "LIV", "name": "客厅", "rect": { ... } }
```

`rect` 格式同家具。目前用于把坐标映射回房间名，方便表达层说"主卧"而不是坐标。

## 从真实数据生成

AR 扫描/户型识别模块产出坐标后，按上面的字段映射即可。需要注意两个常见坑：

1. **门法线方向**：从门洞两侧的墙体判断哪边是室内，别默认朝北。
2. **家具 heading**：床的 heading 是**脚的方向**，很多模型导出的是"模型正面朝 +Z"，两者常差 180°，映射时确认一次。
