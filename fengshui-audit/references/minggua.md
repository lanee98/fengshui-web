# 八宅派命卦模块（文化参考层）

## 定位

这个模块**不在 18 条空间判定里**，也不该往里挤。

它读取居住者的出生信息，按八宅派约定算出命卦，与宅向比对，输出一段**标注为文化参考**的文字。结果放在输出的 `culture_reference` 字段，**不进入 `violations`、不参与 severity 计数、不改变任何一条空间规则的结论**。

这么切分的原因很直接：

| | 18 条空间规则 | 本模块 |
|---|---|---|
| 能否用国标/人体工程学支撑 | 能，每条都有第二条腿 | 不能，纯流派约定 |
| 结论是否随人变化 | 不变，只看户型 | 变，同户型换人结论就变 |
| 输出位置 | `violations`，计入统计 | `culture_reference`，单独成段 |
| 能否生成改动建议 | 能，带 `fix` 可直接执行 | **不能**，只作说明 |

**默认关闭**，加 `--culture` 才启用。这是产品判断不是技术限制：被问"你们这是设计工具还是算命软件"时，默认状态本身就是回答。

## 输入

写在场景 JSON 的 `meta.owner` 里：

```json
"meta": {
  "owner": { "birth_year": 1998, "birth_md": "06-15", "gender": "female" }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `birth_year` | 是 | 出生年份（公历）。用四位年份 |
| `gender` | 是 | `"male"` / `"female"`。命卦男女算法不同，不能省 |
| `birth_md` | 否 | `"MM-DD"`。给了才会做立春校正 |

## 算法

### 命卦

采用**锚点 + 取模**，不用网上常见的「100 − 年份后两位」那类公式：

```
男命 = (7 − (year − 1984)) mod 9
女命 = (8 + (year − 1984)) mod 9
余 0 记作 9
```

锚点是 1984 年（甲子年）：男命兑(7)、女命艮(8)。命卦九年一循环，男女方向相反。

**为什么不用常见公式**：`(100 − 年份后两位) % 9` 在 1999 → 2000 处不连续，会把 2000 年以后出生的人算错。锚点法跨世纪无缝，已逐条对过通行命卦表。

### 卦序与分组

| 卦号 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 卦名 | 坎 | 坤 | 震 | 巽 | 中 | 乾 | 兑 | 艮 | 离 |

- **东四**：坎(1)、震(3)、巽(4)、离(9)
- **西四**：坤(2)、乾(6)、兑(7)、艮(8)

**5 黄**：无对应卦位。男寄坤(2)，女寄艮(8)。输出里 `substituted_from_5: true` 会标出来。

### 宅向

- **向** = 入户门的**外法线**方向（门朝外的那一边）
- **坐** = 向的反向（+180°）

| 坐向 | 宅卦 | 分组 |
|---|---|---|
| 北 | 坎 | 东四宅 |
| 南 | 离 | 东四宅 |
| 东 | 震 | 东四宅 |
| 东南 | 巽 | 东四宅 |
| 西 | 兑 | 西四宅 |
| 西北 | 乾 | 西四宅 |
| 西南 | 坤 | 西四宅 |
| 东北 | 艮 | 西四宅 |

### 配不配

命与宅**同组**（都东四或都西四）→ 该派认为相配。跨组 → 该派认为不相配。

注意：判断比较的是**分组本质**，不是标签。`东四命` 与 `东四宅` 两个字符串永远不相等，拿标签比会把所有情况都判成不相配（这个 bug 在实现时真踩过）。

### 立春校正

传统以**立春**为年份分界，不是元旦。本实现用 2 月 3 日近似：

- `birth_md` 在 1 月 1 日 ~ 2 月 3 日之间 → 命卦按上一年计
- 立春实际在 2 月 3–5 日之间浮动，边界日可能偏差一天

**没有接节气数据**。要严格就得引入天文算法或节气表，当前版本明确不做到这一步。

## 已知局限（必须随输出一起给出）

1. **流派分歧**：八宅、三合、玄空对宅命关系的判法不同。本模块只取八宅一派，不能表述为定论。
2. **年份分界为近似**：见上节。
3. **5 黄寄宫是约定**：男寄坤、女寄艮属通行做法，不同资料有出入。
4. **无科学支撑**：宅命是否相配属文化观念，找不到国标或人体工程学对应物，不作为设计依据。

这四条已经硬编码在输出的 `limits` 数组里，任何调用方都会拿到，不靠提示词"记得说"。

## 出处

🔶 **二手转引，原书待核。**

八宅派命卦配宅的系统论述通常归于《八宅明镜》（托名唐·杨筠松，一说明人所辑）。本仓库**未收录该书原书**，也未核到具体版本与页码。

当前算法的依据是通行命卦表与公开流传的计算法，属**二手整理**。引用时应表述为「据八宅派通行说法」，**不要报书名页码**——报了就是编。

若要补齐证据链，需要：

1. 找《八宅明镜》可靠整理本（注意托名问题，版本极多）
2. 核对命卦表与原书是否一致
3. 核对 5 黄寄宫的原书记载
4. 若原书说法与通行表冲突，以原书为准并记录差异

在补齐之前，这个模块的定位就是**明确标注的文化参考**，不是有据可依的规则。这一点不能含糊。

## 调用

```bash
# 默认不启用
python scripts/check.py --scene assets/demo_scene.json

# 启用文化参考
python scripts/check.py --scene assets/demo_scene.json --culture --format md
```

单独验证算法：

```python
import sys; sys.path.insert(0, "scripts")
import minggua
minggua.ming_gua(1990, "male")     # (1, False) → 坎，东四命
minggua.ming_gua(1986, "male")     # (2, True)  → 5 黄寄坤
minggua.ming_gua(2000, "female")   # (6, False) → 乾，西四命
```

## 三条禁止

1. **不得据此生成改动建议。** 输出里不能出现"建议把床头转向X方以合命卦"。那是把文化解释伪装成设计结论。
2. **不得做吉凶断言。** 不说「不配则不利」「相配则兴旺」。只说「该派认为相配/不相配」。
3. **不得隐藏局限。** `limits` 必须随结果一起出现，不能只在被追问时才说。
